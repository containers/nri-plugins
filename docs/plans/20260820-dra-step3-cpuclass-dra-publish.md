# DRA v1 step 3 — `cpuClass.dra.publish` config field + `ValidateCPUClassesForDRA`

## Overview

Adds opt-out DRA visibility control to the `CPUClass` config type: a new `cpuClass.dra` sub-block with a single `publish *bool` field (default `true`). Also introduces `ValidateCPUClassesForDRA` — a validation function called at driver Configure time that refuses to start when multiple published PCT classes exist in the same tier without `sharedCounters` enabled.

This step is **config API and one new validation function** — no driver code, no punit enumeration at runtime. The `CPUClassDRA` type lives in the CRD config package; `ValidateCPUClassesForDRA` lives in `pkg/resmgr/cpuclass/` (which already imports `policyapi`) so the CRD API package stays clean.

**Companion docs:** [design.md §"v1 approach"](../dra/design.md#v1-approach-no-kep-5941-per-class-opt-out-refuse-to-start-on-residual-ambiguity), [plan.md Step 3](../dra/plan.md).

## Solution Overview

### Config API (`pkg/apis/config/v1alpha1/resmgr/policy/cpuclass.go`)

New type `CPUClassDRA` (name matches `docs/dra/plan.md`):

```go
// CPUClassDRA holds per-cpuClass DRA publication options.
// +k8s:deepcopy-gen=true
type CPUClassDRA struct {
    // Publish controls whether this cpuClass is exposed as a DRA device.
    // Defaults to true when unset. Set to false to hide this class from
    // DRA while keeping it usable via the normal nri-plugins config path.
    // +optional
    Publish *bool `json:"publish,omitempty"`
}
```

New field on `CPUClass`:

```go
// DRA holds DRA publication options for this class. Optional; defaults
// to publish=true.
// +optional
DRA *CPUClassDRA `json:"dra,omitempty"`
```

New getter (unambiguous name avoids collision with `PublishExtendedResource`):

```go
// DRAPublish reports whether this cpuClass should be published as a DRA device.
// Returns true if DRA is nil or DRA.Publish is nil.
func (cc *CPUClass) DRAPublish() bool {
    if cc.DRA == nil || cc.DRA.Publish == nil {
        return true
    }
    return *cc.DRA.Publish
}
```

### Validation function (`pkg/resmgr/cpuclass/dra.go`)

Tier classification — **static, from config only** (no hardware reads, no punit mapping):

- Managed PCT (`PctPriority != ""`): tier = `PctPriority` value (`"high"` or `"low"`).
- Assoc-only PCT (`SstClosID != nil`): tier = the `SstClosID` integer (each CLOS ID is its own tier; different CLOSes can have different frequencies).
- Non-PCT classes (`PctPriority == "" && SstClosID == nil`): **exempt from the tier check** — they have no turbo-frequency tier concept and the overcommit risk doesn't apply. They are still subject to `DRAPublish()` and are published as DRA devices when published=true (Step 5 handles all published classes, not PCT-only).

```go
// ValidateCPUClassesForDRA checks that DRA-published PCT classes do not
// overcommit any priority tier. Called at driver Configure time, not at
// config load time. Returns an error naming the conflict and its two
// resolutions (opt out via dra.publish: false, or enable sharedCounters).
func ValidateCPUClassesForDRA(classes []*policyapi.CPUClass, sharedCounters bool) error
```

Note: `[]Punit` is **not** a parameter in v1. Since `CPUClass` carries no punit affinity, tier-level validation is the only static check computable from config. Per-punit enforcement arrives in Step 5 (`cpuclass.Manager.DRADevices()`) where runtime punit topology is available.

## Technical Details

### Tier key (for `ValidateCPUClassesForDRA`)

A single `string` label doubles as the grouping key and the error-message label:

- Managed: `"pctPriority=high"` or `"pctPriority=low"`.
- Assoc-only: `"closID=<N>"`.

(Note: `ValidateCPUClasses` already forbids mixing managed and assoc-only classes, so a combined struct is unnecessary.)

For each tier, count DRA-published PCT classes. If any tier has >1 published class and `sharedCounters == false`, return a formatted error that:
1. Names the tier (e.g. "managed pctPriority=high" or "assoc-only CLOS 2")
2. Lists the conflicting class names (sorted, for deterministic output)
3. Points at the two resolutions: set `dra.publish: false` on all but one, or enable `sharedCounters: true`
